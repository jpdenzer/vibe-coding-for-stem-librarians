# Contributing & Feedback

Thanks for helping make this resource better! It's meant for librarians with little or no programming background, so feedback from that point of view is especially welcome.

## Quick feedback (no GitHub experience needed)

- **Found an error or something confusing?** [Open an issue](https://github.com/jpdenzer/vibe-coding-for-stem-librarians/issues/new) and describe it in plain English. You'll need a free GitHub account.
- **Install steps out of date?** AI tools change fast. Please tell us which page and what changed, with a link to the official docs if you have one.
- **Attended the talk?** Comments on what was most and least useful are very welcome as an issue.

## Suggesting an edit directly

Every page on the website has a **"Suggest an edit to this page on GitHub"** link at the bottom. Clicking it opens the page's text on GitHub, where you can make a change and propose it (GitHub calls this a *pull request*). GitHub walks you through each step.

## Contributing an example

Have a vibe-coded library project you'd like to share? Open an issue first to describe it. Examples should follow the format on the [Real-World Examples](examples/real-world/) page: the original prompt, what the AI produced, what went wrong, and how the result was validated.

## Ground rules

- **No real data, ever.** No patron or student information, credentials, API keys, proxy details, or licensed vendor content. Use fake data and placeholders. See [Guardrails](guardrails.md).
- **Keep it jargon-light.** If you use a technical term, explain it the first time.
- **Flag things that change.** Prices, plan limits, and install commands should link to official docs with a "check the official docs" note.
- **Be kind.** Everyone here is learning.
